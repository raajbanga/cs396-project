11.[x] GET /api/export?type=…&<params> → text/csv, Content-Disposition
       attachment, JSON 400/404 on a bad request (src/server/export.ts).
       One shared CSV writer src/lib/csv.ts (RFC 4180 quoting of comma, quote,
       CR/LF; CRLF lines) + csv.test.ts.
12.[x] Types: dataset (id → every unit-year it holds + audit_flags column),
       valid (id → that dataset's records with no audit flags), invalid
       (id → data-quality report: import_issues rows + original columns, plus
       one FLAGGED row per audit flag of the dataset's records), search (the explorer's
       own URL params via parseExplorerParams; Facilities or Units, table
       order, no paging, rank column with First N), selection (ids/unitIds →
       every year of the compare selection), provenance (all datasets or one:
       source, params, file, dates, counts, current records, status).
       No forked query paths: getFacilities/getUnitYears/getDatasets now call
       exported rankedFacilities / rankedUnitYears(scope) / datasetHistory.
       NOTE: "valid" = unflagged records. Uploads and syncs share one write path
       (rejected rows never become records), so "accepted rows" alone would just
       repeat "dataset". Facility-only uploads own no annual records, so their
       dataset/valid exports are empty (header only).
   [x] §10 re-check: invalid now also lists questionable (audit-flagged)
       records, so it works for CAMPD datasets too (valid + flagged = dataset);
       unit-year CSVs gained §7 fields program_code, hg_controls,
